# 演示视频：台词与执行（板子 + 网页控制端）

> 画面只有两个来源：**手机拍板子**（主画面）与**录屏网页控制端**（画中画）。
> 旁白用小米的模型生成，逐段生成、逐段对齐。**台词合计 971 字，约 3 分 35 秒**；
> 加上镜头之间的停顿，成片约 **3 分 50 秒**，离 5 分钟上限还有约 1 分钟余量
> （余量怎么用见第七节）。
> 文件命名按段号：`01.mp3` … `07.mp3`。

## 二、台词（逐段，可直接喂 TTS）

**怎么用**：把每段的【配音】整段复制进 TTS，生成 `01.mp3`…`07.mp3`。别把【字幕】也念进去——字幕是给画面用的，里面有些词 TTS 念不好（见第三节）。括号里的"可删句"是这一段的备用句，配音超时就从这里砍。

### 段 1（21 秒） ｜ 开场：这是什么

- **配音**（约 96 字 / 21 秒）：这块板子是大赛官方发的思澈开发板。板子上麦克风、功放、喇叭座全都有，可出厂的时候它一句声音也发不出来，因为系统里根本没有音频驱动。我们做的第一件事，就是让它能听、能说；再往后，是让它听懂一句话，并且真的把设备控下来。
- **字幕**：SF32LB52-DevKit-LCD 出厂无音频驱动，麦克风与功放不可达。本项目的起点是让它能听、能说。
- **可删句**：无（这段短，别删）。

### 段 2（45 秒） ｜ 项目全貌：三层交付 + 网关

- **配音**（约 203 字 / 45 秒）：整个项目分三层。最底下是音频底座，我们给这颗芯片从零写了 NuttX 的音频驱动，四十八千赫采集、零丢包，喇叭也能出声。中间这层是 IP 承载，因为这块板子没有任何网卡，我们就在串口上跑了 P P P，让它拿到自己的地址。最上面这层是 AI，我们把 openvela 官方的端侧 Agent 引擎移植到了这块板子上，官方支持列表里它是第四块，也是 armv8 架构上的第一块。右边这块是 S3 网关，它同时干三件事：当 P P P 服务端、当网络出口，还跑我们自己训的中文意图分类器。
- **字幕**：三层交付：NuttX 音频 lower-half 驱动 / UART2 PPP 承载 / openvelaClaw 引擎移植；ESP32-S3 网关兼做 PPP 服务端、NAT 与本地意图分类器。
- **可删句**："官方支持列表里它是第四块，也是 armv8 架构上的第一块。"（这句评审爱看，尽量留）

### 段 3（39 秒） ｜ 测试流程 第 1 步：一句话，本地闭环

- **配音**（约 177 字 / 39 秒）：先看完整流程的第一步。我在这张网页上点一下"打开台灯"。请注意，网页只是替我把一句话敲进板子的控制台，真正去问网关的是板子自己。板子把这句话送到 S3，S3 上跑的是我们自己训的中文意图分类器，字符一到三元组做哈希，线性分类，中文测试集全部答对。它判断出这是"打开台灯"，直接用米家的局域网协议发一条指令出去。板子这边，屏幕上出现中文，喇叭播的是预先合成好、烧在固件里的离线语音，整个过程不需要联网。
- **字幕**：网页 → 板子 → S3 本地分类器 → 米家局域网协议；播报来自固件内置的离线语音片段。
- **可删句**："字符一到三元组做哈希，线性分类，中文测试集全部答对。"（技术点，若删请把字幕留下）

### 段 4（36 秒） ｜ 测试流程 第 2 步：断网控米家（核心镜头）

- **配音**（约 160 字 / 36 秒）：现在做最关键的一步。我把手机的移动数据关掉，云端的大模型、云端的语音合成，现在都够不着了，只剩下这张局域网。我照样在网页上点：关闭客厅的灯、台灯调暖一点、打开空调。右边这个终端是米家官方开源的模拟器，能看到它收下指令、设备状态真的跟着变。这三句话没有走出过局域网，也不经过米家的云。网页上"最近路由"这一行会记下每一句话走了哪条路，是本地判断的，还是走了云端。
- **字幕**：关掉移动数据（保留热点）后口令仍全部执行；被控端为 python-miio 官方模拟器，设备状态由网页直连设备读回。
- **可删句**："网页上'最近路由'这一行……走了云端。"（这句和段 6（27 秒） 重叠，若整体偏长可只保留一处）

### 段 5（28 秒） ｜ 测试流程 第 3 步：板载灯与状态屏

- **配音**（约 127 字 / 28 秒）：同一套本地模型，也能控制网关这块板子上的 R G B 灯。"打开 R G B"、"红灯闪三下"，同样是本地判断，没有联网。再看板子的屏幕：白底、大字，上面五行都是实时读数——最近一条指令、网关链路、本地模型的调用次数、刚才播的是哪条语音、已经执行了多少条。链路断了这几行会变，因为它们不是写死的，是运行时读出来的。
- **字幕**：板载 RGB 由同一分类器驱动；屏幕五行均为运行时真实读数（链路取自 getifaddrs，模型与计数取自 LLM 路由运行时）。
- **可删句**："链路断了这几行会变……"（可选）

### 段 6（27 秒） ｜ 测试流程 第 4 步：把证据放上台面

- **配音**（约 123 字 / 27 秒）：这套东西不只是能跑，还得能查。这张网页就是我们的测试台：它直连设备读回真实状态，不信任任何缓存；事件流里每条指令都记着耗时、走了哪条路、播报的是哪个语音片段；板子自己问出去的话，也会出现在这里。演示里每出现一句话，你都能在上面找到它是谁处理的、花了多久、设备到底有没有变化。
- **字幕**：网页直连设备读取真实状态（不走缓存）；事件流记录耗时、路由与播报片段名。
- **可删句**："板子自己问出去的话，也会出现在这里。"

### 段 7（19 秒） ｜ 收尾

- **配音**（约 85 字 / 19 秒）：代码、补丁、测试证据都在仓库里，分支名 dev-ai-contest-2026。每一层的实测数据，包括没做到的部分，都分开写在文档里。队伍 TinyMind，作品 TinyMind-Audio。
- **字幕**：open-vela/contest2026_434_TinyMind · 分支 dev-ai-contest-2026 · 队伍 TinyMind（434）· 作品 TinyMind-Audio
- **可删句**：无。

## 三、发音替换表（TTS 念不好的词）

配音文本里我已经按"读得顺"写好了，字幕里保留正式写法。若你想改回正式写法，注意下面这些：

| 正式写法 | 配音里的写法 | 说明 |
|---|---|---|
| SF32LB52-DevKit-LCD | 思澈开发板 / SF32LB52 | 逐字母念太长，口播用"思澈的这块开发板" |
| openvelaClaw | openvela（官方的端侧 Agent 引擎） | 连写容易被念乱，拆开说或省略 |
| PPP | P P P | 分开写更容易按字母念 |
| RGB | R G B | 同上 |
| miIO / python-miio | 米家的局域网协议 / 米家官方开源的模拟器 | 别让 TTS 去拼 "miio" |
| 48 kHz / 16 bit | 四十八千赫 / 十六位 | 数字+英文单位最容易念错 |
| overruns=0 | 零丢包 | 符号 TTS 会跳过 |
| 16/16 | 全部答对 | 同上 |
| 10.0.0.2 | 自己的地址 | 口播报 IP 没意义，字幕里给数字 |

## 四、录制怎么做（这一节解决"具体怎么执行"）

### 4.1 摆好现场（10 分钟）

| 项 | 怎么弄 |
|---|---|
| 手机 | **横屏**、固定在支架上，距离板子 30–50 cm，稍微俯拍；板子屏幕要清晰可读，喇叭出声能被手机收进去 |
| 板子 | 桌面平放，屏幕朝镜头；插 USB 供电 + COM5；与 S3 之间三根杜邦线（GPIO17→PA20、GPIO18←PA27、GND↔GND，不接 VCC） |
| S3 网关 | 插 COM10，Wi-Fi 连手机热点，上电就是网关，不需要 PC 参与 |
| 被控端 | PC 上开一个终端跑官方模拟器：`miiocli devtools miio-simulator --file 工具/pc_side/yeelight_lamp.yaml` |
| 网页控制端 | 另一个终端跑：`python 工具/pc_side/tinymind_panel.py --gateway <S3 的 WiFi 地址> --board-console COM5 --sftool 工具/sftool.exe --image 固件/nuttx-ai_agent-screen-voice3.bin`；浏览器开 **http://127.0.0.1:8080**，按 F11 全屏 |
| 屏幕布局 | 同一个显示器上**左 2/3 放网页、右 1/3 放模拟器终端**（这样一条录屏里同时有"谁收下了指令"和"设备真的变了"） |
| 录屏 | OBS（或系统录屏）**显示器采集**，1080p / 30fps，无声音（声音后期来自 TTS，板子的喇叭声由手机收） |
| 手机数据 | 连热点，**录到第 4 镜时在镜头前关掉移动数据**（热点别关） |

### 4.2 录制顺序（一遍过，别停）

1. 手机开始录 → 停两秒 → OBS 开始录 → 停两秒。
2. 镜头 1：手拿板子转一圈（说段 1（21 秒） 的内容，但配音后期贴，现场只要**动作**）。
3. 镜头 2：板子放回桌面，网页全屏，鼠标停在网关卡那几行（停 5 秒）。
4. 镜头 3：点一次 `打开台灯`，等板子出完屏和声，再等 3 秒。
5. 镜头 4：**在镜头前关手机移动数据**（手要入画）→ 依次点 `关闭客厅的灯`、`台灯调暖一点`、`打开空调`，每句等它出完。
6. 镜头 5：在"说一句"输入框里输入 `打开RGB` 按回车，再输入 `红灯闪三下` 按回车（这两句没做成快捷按钮）。然后把手机靠近板子屏拍五行读数。
7. 镜头 6：鼠标在网页上慢慢划过 `最近路由`、`板子刚问`、设备卡（每处停 2 秒）。
8. 镜头 7：板子和网页同框，收。
9. 停 OBS → 停手机。**现场不用念台词**（念了后期也要盖掉），但要按动作顺序走。

> 为什么现场不念台词：TTS 是后期贴的，现场念了反而在对齐时互相干扰。所以录制时只需要"动作对、画面清"。

### 4.3 对齐（后期唯一需要点耐心的地方）

- 先把 7 段旁白按顺序铺在音频轨（间隔 0.4 秒），**时间轴就定了**。
- 再把画面按下面的"锚点"对上去：
  - 段 3（39 秒） 的锚点 = 板子**屏幕第一次出现"台灯已打开"**的那一帧；
  - 段 4（36 秒） 的锚点 = 手**离开手机（数据关掉）**的那一帧；
  - 段 5（28 秒） 的锚点 = S3 **板载灯亮起**的那一帧；
  - 段 6（27 秒） 的锚点 = 鼠标**划过"最近路由"**那一帧。
- 对不齐就**剪画面**（前面对齐点切掉/加速），**不要剪旁白**。

## 五、剪辑（剪映专业版，PC）

1. 新建项目：1080p、30fps。
2. 导入：手机视频、OBS 录屏、7 段旁白。
3. 主轨放手机视频；OBS 录屏放**画中画**轨，缩到右下角约 40%，加细描边（不然融在背景里）。
4. 音频轨放 7 段旁白，段间留 0.4 秒。
5. 按 4.3 的锚点对齐画面；等待段落用"变速 2.0x"或直接切。
6. 字幕：`文本 → 智能字幕 → 识别字幕`（识别旁白音频）→ 用第二节的【字幕】逐条订正专有名词（识别会把 SF32LB52、miio、openvela 认错）。

8. 片头 2 秒标题卡：`TinyMind-Audio · 基于 openvela 的 SF32LB52 板载音频子系统适配 · 队伍 TinyMind（434）`。

## 六、录前自检（3 分钟，务必做完再按录制）

1. 网页顶部三行：`链路 Wi-Fi up`、`板子 PPP session up (10.0.0.2)`、两张设备卡都是绿的（在线）。
2. 试点一句 `打开台灯`：板子屏出"台灯已打开"、喇叭出声、事件流末尾是 `面板代问 · 板子播报 clip 'lamp_on'`。**三处都对**才算链路热了。
3. 板子屏最上面那行"运行时长"在走（说明屏是真的在刷新）。
4. 模拟器终端有输出（不报错）。
5. 7 段旁白已经生成并听过，时长与表里接近。
6. 手机：静音模式、通知关掉；支架固定；电量够（或插电）。
7. 房间安静；手机离板子 30–50 cm。

失败处置：

- **板子卡住**（屏不动、网页提示"你没回话"）：镜头外点网页上的 `↻ 复位板子并重连`，等 30 秒，接着录，不用重来。
- **某一句没响应**：重说一遍即可；不要为一句重录整条片子。
- **喇叭声没收进去**：手机靠近板子 20 cm，或用剪映把这段音频增益 +6 dB。

## 七、常见坑

- 别连点：每句话等板子出完（约 5–10 秒）再点下一句。
- 面板上的快捷按钮只有台灯/空调；`打开RGB`、`红灯闪三下` 要**在输入框里打字后按回车**（发送按钮在窗口右缘，可能被裁掉，回车一样能提交）。
- `↻ 复位板子并重连` 就是复位键：它会先把芯片从下载态带出来，不行才整包重烧（约 33 秒）。演示中途卡了直接点它。
- 网页只能有一个进程占用 COM5：**别同时再开一个终端连板子控制台**，会和网页抢串口。
- 录屏和手机是两条独立素材，对齐靠锚点帧，不要求同一时刻开始。
- 总时长宁短不长：超了就砍段 4 或段 6 的"可删句"，别加速旁白。
- **余下的约 1 分钟怎么用**：优先给画面留呼吸（每段旁白前后多停 0.5 秒、点完按钮多等两秒、让板子的屏幕和声音完整出现）；有余力再补两个空镜（板子屏特写、面板设备卡特写各 15 秒）垫在段 2 和段 6 上。**不要**为了凑时长去加没实测过的内容。
