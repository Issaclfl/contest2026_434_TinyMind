# 演示视频拍摄脚本（≤ 5 分钟）

> 官方要求：Demo 演示视频，**不超过 5 分钟**，随压缩包提交。
> 本文是逐镜脚本，照着录即可。命令都是可直接复制的。

---

## 一、录制前准备（10 分钟）

| 项 | 说明 |
|---|---|
| 屏幕录制 | 用 OBS / 系统自带录屏 / 手机拍屏都行。**建议 OBS 录屏 + 手机补拍实物** |
| 终端窗口 | 一个串口终端连板子控制台：**COM5，1000000 8N1，关闭流控** |
| 分辨率 | 1080p 即可；**终端字号调大**（建议 16–18pt），否则手机上看不清 |
| 已烧固件 | 板子：`固件/nuttx-ai_agent-latest.bin`（**2249088 字节，md5 `4fa0eade7844`**，含 `nxplayer` 与放音/采集通道修复）；S3 网关：本仓库 `esp32s3_gateway`，插在 COM10 |
| 网络 | 手机热点（电脑与 S3 都连它）；板子插上 **USB 供电 + COM5**，与 S3 之间三根杜邦线：GPIO17→PA20、GPIO18←PA27、GND↔GND（**不接 VCC**）|
| 手机 | 也连这个热点，浏览器书签存 **`https://<S3 的地址>/talk`**（自签证书，第一次点一次"继续前往"）。录镜 6 之前先自己按一次：**第一次按会弹麦克风权限框，那一按录不到东西**（页面会提示"先点允许，再按住一次"），点允许之后第二次按就正常了——所以正式录之前先按两次热身，别让镜头拍到第一次 |
| 可选：接线 | USB-TTL 接板子 UART2（PA20=RX / PA27=TX / GND），能拍第 5 镜 |
| 可选：喇叭 | 4Ω ≤3W 喇叭接板上 **2.0mm 2P 母座**（功放输出，板载 Class-D，使能线 PA10）。接上就能拍镜 2 的放音——`nxplayer` 已在新固件里启用 |

**录之前先跑一遍**，确认每条命令的输出都在，避免录到一半发现某步不通。录制前
板子应该是干净的 NSH 提示符（`ps` 里只有 idle/hpwork/lpwork/nsh），两条命令在
镜 5 里现敲；S3 一上电就是网关，不需要 PC 参与。

## 二、逐镜脚本

### 镜 0（0:00–0:20）开场 —— 讲清痛点

**画面**：板子实物特写（手拿板子转一圈，露出麦克风与喇叭座）。

**旁白**：
> 这块板子是大赛官方提供的 SF32LB52-DevKit-LCD。官网把它定位成"蓝牙音频终端"，
> 板载麦克风、功放、喇叭座、片内音频编解码器全都焊好了——**但出厂时没有音频驱动**。
> 整块板子是个哑巴。我们做的第一件事，就是给它装上耳朵和嘴。

---

### 镜 1（0:20–1:00）音频底座：设备注册

**画面**：终端窗口。

**操作**：敲

```
uname -a
ls /dev
```

**要指出的输出**：`/dev` 列表里的 **`audio0`**。

**旁白**：
> 这是我们为这块芯片从零写的 NuttX 音频 lower-half 驱动。适配前，
> 板级支持里 `grep audio / codec / i2s / pdm` 没有任何命中；现在系统里
> 多出了标准的音频设备 `audio0`，应用可以用通用的 open/ioctl/read 接口访问它。

---

### 镜 2（1:00–1:50）音频采集：真机录音（**核心证据，别剪掉**）

**画面**：终端窗口 + 板子实物同框（对着麦克风说话/拍手）。

**操作**：敲

```
nxrecorder
device /dev/audio0
recordraw /data/demo.pcm 2 16 48000 0
```

> 采集参数写死这几个数：**放音时要用同一组**（`playraw /data/demo.pcm 2 16 48000 0`），
> 对不上会放成怪声。板载只有一颗麦克风，所以 2ch 时右声道是 0——录像里别把它说成
> "立体声"，说"48 kHz/16bit 采集"就够。

**对着板子的麦克风说话约 10 秒**，然后敲

```
stop
q
ls -l /data
```

**要指出的输出**（这两行是这条视频最有说服力的部分）：

```
sf32lb52_audio_hw_config_capture: capture config: 48000Hz 2ch 16bit
sf32lb52_stop: stop: overruns=0
```

**紧接放音回放（约 25 秒，喇叭已接、出声已人耳确认，非常值得拍）**——把刚录到的声音从板子喇叭放出来：

```
nxplayer
device /dev/audio0
playraw /data/demo.pcm 2 16 48000 0
```

**要指出的输出**（放音链路走完、会话自动结束，是"哑巴板子开口"的硬证据）：

```
sf32lb52_audio_hw_start: playback started (staging 16384 B, circular)
sf32lb52_serve_half: playback: final buffer served, draining staging
sf32lb52_stage_callback: playback: end of stream, COMPLETE queued
sf32lb52_stop: stop: done (complete already delivered)
```

> 敲 `q` 退出 nxplayer 再回到后面的镜头。**注意**：这条回放已人耳确认有声
> （2026-09-19 实测：先 1 kHz 纯音、后录音回放，两段可分辨）；如果现场环境嘈杂、
> 手机收不进喇叭声，就把手机贴近板子。音频证据
> `docs/audio-evidence/playback-loop-48k-stereo.log` 里是同一套命令的完整串口记录。
>
> 时间不够就把这一段的 25 秒砍掉（镜 6 之后的可选新动作那 30 秒同理，二选一）。

**旁白**：
> 48 kHz、16bit 采集，`overruns=0` 意味着**全程零丢包**——环形缓冲与中断接力
> 一次都没有断。落盘文件有几十万字节。采集确实在跑，不是空转。
> 现在把这段录音从板子的喇叭放回去：驱动把最后一桶数据标了 `AUDIO_APB_FINAL`，
> 播完自己交 `COMPLETE`，会话干净结束——这一整条放音通路也是我们从零写的。

---

### 镜 3（1:50–2:30）AI Agent 在板子上启动

**画面**：终端窗口。

**操作**：敲

```
ai_agent
```

**等待约 15 秒**，让启动日志滚完。**要指出的输出**：

- `[boot +15ms] heap: arena=8743504 free=8330488` （8.7 MB 堆，PSRAM 已在里面）
- `[tools] Tools JSON built (36 builtin + 0 providers)`
- `[skills] Installed built-in skill: /data/ai_agent/skills/...`
- 最后的 `vela>` 提示符

**旁白**：
> 这是 openvela 官方的端侧 AI Agent 引擎，也就是官网说的 openvelaClaw。
> 官方支持的板子原本只有 QEMU、ESP32-S3 和 Gemini-S1 三块，
> **SF32LB52 是第四块，也是 armv8-m 架构上的第一块**。
> 启动后 36 个工具全部注册，Skills 系统也装好了。

---

### 镜 4（2:30–3:10）配置模型

**画面**：终端窗口。

**操作**：敲

```
set_llm http://10.0.0.1/v1 auto local
```

**要指出的输出**：
```
[llm_router] Backend 0 configured: 10.0.0.1
[llm] LLM config updated atomically: 10.0.0.1/v1/chat/completions (model: auto)
LLM backend: 10.0.0.1:80/v1/chat/completions (model: auto) [router slot 0]
```

> ✅ **这条就是设计的重点，值得停两秒**：板子上写的是"网关地址 + 模型名 auto"，
> 第三个参数是个占位值——**云端的 API key 从头到尾不在板子上**，它只在 S3 网关的
> gitignore 配置里。所以这一镜**不会露出任何 key**，不需要打码。

**旁白**：
> 板子上没有写任何云端地址和密钥，只认一个地址：`10.0.0.1`，也就是旁边那块
> ESP32-S3 网关。有网时网关把请求转给云端大模型，**没网时用 S3 上跑的小模型顶上**——
> 对板子来说永远是同一个地址、同一种协议，断网与否由网关判断。
> 密钥只存在网关里，从不下发到板子。

### 镜 5（3:10–4:20）**端到端对话：上网 + 云端作答**

**画面**：终端窗口（板子控制台）。

**操作**：敲

```
pppd /dev/ttyS0 460800 &
```

等约 5 秒（S3 那一侧会自动完成 LCP 协商），然后敲

```
ifconfig
ping 223.5.5.5
```

**要指出的输出**：

```
pppd: /dev/ttyS0 at 460800 baud, direct link
ppp0  Link encap:TUN at RUNNING mtu 1500
      inet addr:10.0.0.2 DRaddr:10.0.0.1 Mask:0.0.0.0
...
10 packets transmitted, 10 received, 0% packet loss
rtt min/avg/max/mdev = 60.000/68.000/80.000/7.483 ms
```

然后问一句（**每轮换一个新问法**，板子会把相同问题缓存，第二次 latency=0 不发请求）：

```
ask In one sentence, what does a microcontroller do?
```

**要指出的输出**：`[trace:...] llm=ok backend=0` 与随后的英文回答（约 10 秒）。

**旁白**：
> 板子上没有任何网卡：没有 WiFi 驱动、没有以太网 MAC、片内 USB 只是串口。
> 我们把 UART2 当成了 IP 承载，460800 波特率的 PPP，对端就是这块 S3。
> S3 同时做 NAT——板上 `ping 223.5.5.5` 十个包零丢包，平均 68 毫秒。
> 于是这句话真的走到了云端大模型，回答再原路回来。

**可选的加分镜头（时间够就拍，不够就跳过）**：把手机热点关掉，然后
**改用镜 6 的方式点灯**——`ask switch the green light on`，灯照样变绿。

> 为什么不是"关网再问一个知识问题"：现在 llm 分区里装的是**命令模型**，
> 它只会翻动作 JSON，不会讲英文小故事（讲故事的模型我们另外测过、也在文档里，
> 见台架证据 §九）。所以断网这一段的最强演示是"**断了网它还在控制硬件**"。

> ⚠️ 关热点会让电脑掉网（串口是本地链路，不受影响，继续录即可）。

> **如果这一镜没接通**：改为拍 `docs/ESP32-S3网关台架实测证据.md` 里的实测记录，
> 并如实说明。**不要伪造对话画面。**

### 镜 6（4:05–4:45）**说一句就控制硬件**（自己训、自己量化的模型在干活）

**画面**：手机或电脑的浏览器 + 板子实物同框（**一定要拍到灯变颜色**）。

**操作**：手机连同一个热点，浏览器打开 **`https://<S3 的 WiFi 地址>/talk`**——注意是
**https**，不是 http。第一次会弹证书警告：点 **"高级 / 详细信息" → "继续前往"** 就进去了。
然后按住按钮说一句英文口令，松开。先说：

```
turn on the red light
```

**为什么必须 https**：浏览器只把麦克风给"安全上下文"，`http://` 页面上
`navigator.mediaDevices` 直接是 `undefined`，按住说话**点不动**（第一版就栽在这里：
手机上按下去毫无反应，控制台里只有一句 `Cannot read properties of undefined`）。
所以网关在 443 上又开了一份同样的路由，用一张自签证书。**万一手机就是点不过证书**，
页面自己还有两条替代路：传一段录音文件、或者直接在页面上打字（打字那条完全走本地、
断网也能用）——页面上写清了原因，不会装作能用。

**要指出的输出**（页面上会出现）：

```
{"transcript":"Turn on the red light.","ok":true,
 "result":{"action":"led","color":"red","result":"led set"}}
```

**同时**：S3 板载的 RGB 灯变红。再按住说一句训练集里没有的说法：

```
switch the blue light on
```

→ 灯变蓝，页面上 `{"action":"led","color":"blue","result":"led set"}`。

**旁白**：
> 这一句没有任何云端大模型参与判断。**听的活是云端的**（它把自由说法转成文字），
> **决定做什么是这块板子上跑的、我们自己训的小模型**——0.26M 参数，留出集
> 43/46，压成 int8 之后一样 43/46。动作的词汇表根本不出这块板子：
> 云只返回文字，选哪个动作、点哪个引脚，都是本地决定的。
> 从说完到灯亮，三秒出头。

> 也可以补一句打字的对照（`set_llm http://10.0.0.1/v1 cmd local` 之后
> `ask turn on the red light`，或者在页面下面的输入框里直接敲）——那条路更快
> （1.2 秒）而且**断网也能用**；语音这条腿要联网，因为"听"在云上。

**（可选，再加 30 秒；时间不够就替掉上面那段打字对照）** 同一套流程，换几个动作，
说明它不是只会点灯。都在这一个页面上敲或说：

```
what is the chip temperature      -> {"celsius":45.3,"source":"esp32-s3 internal sensor"}
what is the weather in beijing    -> {"city":"beijing","report":"Beijing: ☁️  +26°C"}
blink the blue light three times  -> 灯闪三下（说的时候用 "three times" 也行，我们专门
                                     把数字的词形也训进去了）
tell me a joke                    -> {"action":"ask","answer":"Why did the AI go to
                                      therapy? Because it had too many deep learning
                                      issues… 😄"}
```

**要指出的点**（旁白）：
> 这几句的关键是**它们不是同一种活**：温度是片内传感器的**真读数**（手指按住 S3
> 的芯片，数字会往上走），天气是从网上取的**真数据**，两个都不是模型编的——模型只
> 负责"选哪个动作"，取数、拼 URL 这些事由代码做，所以模型碰不到网络参数。
> 最后那句是第三类：本地小模型判断的是"**这题该去问云端**"，原话原样转给云端大
> 模型，答案再送回来（这一句慢，8~10 秒，因为云端要"想"）。
> 所以这块板子既能动硬件，也知道自己什么时候该求援。

| 1 | 设备注册 | 0:30 |
| 2 | **真机录音（核心）** | 0:45 |
| 3 | Agent 启动 | 0:30 |
| 4 | 配置模型 | 0:30 |
| 5 | **端到端对话（云端）** | 0:55 |

| 可选段 | 加在哪 | 时长 | 建议 |
|---|---|---|---|
| **放音回放**（`nxplayer playraw`，喇叭里放出刚录的那段） | 镜 2 末尾 | +0:25 | 音频作品建议留这段——它是"驱动把放音也做通了"的唯一画面证据，且**出声已人耳确认**，拍出来必然有声音 |
| 新动作演示（温度/天气/云端问答/闪灯） | 镜 6 之后 | +0:30 | 想秀命令模型的广度就留这段 |

选了放音就把镜 2 拉长到 1:10、总长 5:10——**超了**，所以要么砍掉镜 7（收尾 0:20，
可并入镜 6 最后一句话），要么砍掉镜 0（开场 0:15）加压缩镜 4。剪的时候盯住时间轴。

**两处顺序上的坑**（我踩过，写下来省你的时间）：
1. **S3 只要重新烧录或复位，板子的 pppd 就得重起**（板上 `quit` 退出 Agent →
   `pppd /dev/ttyS0 460800 &` → `ai_agent`）。所以录之前先烧好 S3，录的过程中
   不要再碰它的串口。
2. **每轮必须换一个新问法**：板子的 Agent 会缓存相同问题（第二次 `latency=0ms`
   直接返回旧答案，压根不发请求）。镜 5 和镜 6 的问法我都写的是没出现过的句子。

## 四、录制守则

1. **只拍真实发生的**。哪一步没通就如实说没通——报告里也是这么写的，
   视频和文档口径必须一致。
2. **不要加速播放终端输出**。日志滚动本身就是证据，加速会显得可疑。
3. **关键行用鼠标划一下或停顿两秒**，让评委看清 `overruns=0`、
   `36 builtin`、`0% packet loss` 这几个数。
4. 如果某条命令录砸了，**剪掉重录那一段**，不要拼接得看不出操作顺序。
5. **不要在板子上敲 `quit`（也不要敲 `restart`）**。agent 退出或重启之后那块板子的
   控制台就再也不回应了（2026-09-19 实测 `quit`；2026-09-20 实测 `restart` 同样：
   回车、`help`、`ifconfig` 全无回显，软件侧各种 RTS/DTR 与关开端口都叫不回来），
   只能按板载 Reset 或重新烧录救回来。**要重拨 pppd 就直接断电重启板子**：
   到 `nsh>` → `pppd /dev/ttyS0 460800 &` → `ai_agent`。
6. **镜 6 用的是 `https://`**（手机第一次会弹自签证书，点"继续前往"）。要是手机
   死活点不过去，就改拍页面上的另外两条路（传录音文件、打字），
   旁白里说明白"这条路要安全上下文，所以网关自己开了个 TLS 口"。
